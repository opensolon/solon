---
title: "请求参数校验、及定制与扩展"
---

在业务的实现过程中，尤其是对外接口开发，我们需要对请求进行大量的验证并返回错误状态码和描述。在前面的内容中也已经使用过验证机制。


该文将介绍 [solon-security-validation](/article/225) 插件的使用和扩展。能力实现与说明：


| 加注位置 | 能力实现基础 | 说明 |
| -------- | -------- | -------- |
| 函数     | 基于 `@Addition(Filter.class)` 实现     | 对请求上下文做校验（属于注入前校验）     |
| 参数     | 基于 `@Around(Interceptor.class)` 实现     | 对函数的参数值做校验（属于注入后校验）     |


> 版本说明：本文以 `solon-security-validation` 4.0.5 源码为准。

使用效果如下：

```java
//可以加在方法上、或控制器类上（或者控制器基类上）
@Valid
@Controller
public class UserController {
    //
    //这里只是演示，用时别乱加
    //
    @NoRepeatSubmit  //重复提交验证（加上方法上的，为注入之前校验）
    @Whitelist     //白名单验证（加上方法上的，为注入之前校验）
    @Mapping("/user/add")
    public void addUser(
            @NotNull String name, 
            @Pattern("^http") String icon, //注解在参数或字段上时，不需要加 value 属性
            @Validated User user) //实体校验，需要加 @Validated
    { 
        //...
    }
    
    //分组校验
    @Mapping("/user/update")
    public void updateUser(@Validated(UpdateLabel.class) User user){
        //...
    }
}

@Data
public class User {
    @NotNull(groups = UpdateLabel.class) //用于分组校验
    private Long id;
    
    @NotNull
    private String nickname;
    
    @Email  //注解在参数或字段上时，不需要加 value 属性
    private String email;
    
    @Validated //验证列表里的实体
    @NotNull
    @Size(min=1) //最少要有1个
    private List<Order> orderList;
}
```

也可用于组件类上（可以是非 web 项目）

```java
//可以加在方法上、或组件类上（或者基类上）
@Valid
@Component
public class UserService {
    public void addUser(
            @NotNull String name, 
            @Pattern("^http") String icon, //注解在参数或字段上时，不需要加 value 属性
            @Validated User user) //实体校验，需要加 @Validated
    { 
        //...
    }
    
    //分组校验
    public void updateUser(@Validated(UpdateLabel.class) User user){
        //...
    }
}
```

也支持工具手动校验（放哪儿都方便）

```java
User user = new User();
ValidUtils.validateEntity(user);
```

### 校验全部失败 vs 快速失败（solon.validation.validateAll）

默认策略，有校验不通过的会马上返回（快速失败）。如果校验所有，需加配置声明（返回的信息结构会略不同：所有失败项按 `name: message` 格式以"；"拼接，失败项未配置 message 时自动按 `@注解名 verification failed: name` 兜底）：

```yaml
solon.validation.validateAll: true
```

该配置由 `ValidPlugin` 启动时读取，写入全局静态开关 `ValidatorManager.VALIDATE_ALL`（默认 `false`）。运行期还支持**请求级覆盖**：通过 `ValidatorManager.validateAll(true/false)` 在当前线程内临时开启/关闭，用 `clearValidateAll()` 清理（底层为 ThreadLocal，不影响其他线程，见第 6 节『validateAll=true 时的定制处理』）。

#### 三种校验机制下的差异（重要）

| 校验机制 | validateAll=false（快速失败，默认） | validateAll=true（收集全部失败） |
| -------- | -------- | -------- |
| 参数校验（方法参数上的注解） | 首个失败立即走 `failureHandler` 抛出 | **收集所有失败项**，最后统一抛出 `ValidatorException`（消息以"；"拼接；**聚合出口也会贯通 `failureHandler`**） |
| 实体校验（`@Validated` 实体） | 返回首个失败项（`Result.data` 为单个 `BeanValidateInfo`） | **收集所有失败项**（`Result.data` 为 `List<BeanValidateInfo>`） |
| Context 校验（`@Logined`/`@Whitelist`/`@NoRepeatSubmit` 等加在控制器/动作上） | 首个失败立即走 `failureHandler` | **不受影响**：源码 `validateOfContext0` 无 `VALIDATE_ALL` 分支，依然首个失败即停 |

> 注意：Context 校验不受 `validateAll` 控制。若希望这类注解也"收集所有"，需自行实现（见第 6 节的区分处理说明）。

#### validateAll=true 时的失败信息结构

- **参数校验**抛出的 `ValidatorException`：
  - `getMessage()`：所有失败项按 `name: message` 格式以"；"拼接（失败项未配置 message 时自动按 `@注解名 verification failed: name` 兜底，不再出现裸"；"垃圾串）；
  - `getResult().getData()`：`List<BeanValidateInfo>`，每个元素含 `name`（参数名 / `实体类.字段名` / `方法名()`）、`anno`（触发的注解）、`message`（失败消息，可为空串）、`getCode()`（失败项独立错误码）；该列表会**同时合并**参数注解失败项与 `@Validated` 实体字段失败项，用 `name` 可区分；
  - `getAnnotation()` **非 null**：固定为首个失败项的注解（便于 `instanceof` 判断，如官方 `DemoFilter` 的 `Logined` 分支）；
  - `getCode()` **固定为首个失败项的 code**（不再随机取末项）；
- **实体校验**（`ValidUtils.validateEntity` 手动触发时）：失败返回的 `Result.getData()` 为 `List<BeanValidateInfo>`；`ValidUtils.validateEntity` 已支持该结构，抛出的异常 message 为聚合消息、`getAnnotation()` 与 `getCode()` 同样以**首个失败项**为准（旧版本此场景 message 为 null、code 取末项，已修复并对齐参数校验路径）。


Solon 的校验框架，可支持Context的参数较验（即请求传入的参数），也可支持实体字段较验。



### 注解大全

> 说明：所有注解都支持 `message()`（提示消息，为空时框架自动生成默认消息）与 `groups()`（校验分组）两个公共属性，表中不再重复列出。

| 注解  | 作用范围 |  说明 | 
| -------- | -------- | -------- | 
| Valid | 控制器类 / 组件类 / 方法 | 启用校验能力（加在类上，或者基类上；也可加在方法上，只对该方法生效） |
|   | | |
| Validated | 参数 或 字段 | 校验（参数或字段的类型）实体（或实体集合）上的字段。`value()` 与 `groups()` 为别名，如 `@Validated(UpdateLabel.class)` |
|   | | |
| AssertTrue    | 方法 或 字段 | 断言值为 true（支持 Boolean 类型；v3.0+）    | 
| AssertFalse   | 方法 或 字段 | 断言值为 false（支持 Boolean 类型；v3.0+）    | 
| Date    | 参数 或 字段 | 校验注解的值为日期格式（`value()` 为日期表达式，默认为 ISO 格式）    | 
| DecimalMax(value)    | 参数 或 字段 | 校验注解的值小于等于@ DecimalMax指定的value值（小数）     | 
| DecimalMin(value)     | 参数 或 字段 | 校验注解的值大于等于@ DecimalMin指定的value值（小数）     | 
| Email    | 参数 或 字段 | 校验注解的值为电子邮箱格式（`value()` 为自定义正则，默认内置；自定义时必须含 "@"，否则启动即报错）    | 
| Length(min, max)    | 参数 或 字段 | 校验注解的值长度在min和max区间内（对字符串有效，默认 min=0、max=Integer.MAX_VALUE）     | 
| Logined    |  控制器 或 动作 | 校验本次请求主体已登录（`value()` 指定 session 用户标识名，默认 "user_id"）     | 
| Max(value)    |  参数 或 字段 | 校验注解的值小于等于@Max指定的value值（整数）     | 
| Min(value)     | 参数 或 字段 | 校验注解的值大于等于@Min指定的value值（整数）     | 
| NoRepeatSubmit    | 控制器 或 动作  | 校验本次请求没有重复提交（`value()` 指定校验的 HttpPart 集合，默认 {params}；`seconds()` 指定限制秒数，默认 1）     | 
| NotBlacklist    | 控制器 或 动作 | 校验本次请求主体不在黑名单（`value()` 指定黑名单名称）     | 
| NotBlank    | 动作 或 参数 或 字段 | 校验注解的值不是空白（for String）     | 
| NotEmpty    | 动作 或 参数 或 字段 | 校验注解的值不是空（for String 或 Collection）     | 
| NotNull   | 动作 或 参数 或 字段 | 校验注解的值不是null     | 
| NotZero  | 动作 或 参数 或 字段 | 校验注解的值不是0（for 数字类型）     | 
| Null    | 动作 或 参数 或 字段 | 校验注解的值是null     | 
| Numeric    | 动作 或 参数 或 字段 | 校验注解的值为数字格式（整数或小数）    | 
| Pattern(value)    | 参数 或 字段 | 校验注解的值与指定的正则表达式匹配（基于 `find()` 匹配）    | 
| Range(min, max)   | 参数 或 字段 | 校验整数的值在 min 和 max 区间内（v1.11+，默认 min=0、max=Long.MAX_VALUE）    | 
| Size(min, max)   | 参数 或 字段 | 校验注解的集合大小在min和max区间内（对集合有效，默认 min=0、max=Integer.MAX_VALUE）    | 
| Whitelist    | 控制器 或 动作 | 校验本次请求主体在白名单范围内（`value()` 指定白名单名称）     | 


注1：可作用在 [动作 或 参数] 上的注解，加在动作上时可支持多个参数的校验（通过 `value()` 指定参数名数组，如 `@NotNull({"name","type"})`）。

注2：如果 json body 提交的数据，想在 [动作] 上验证，可通过 过滤器 把 json 数据转换部分到 ctx.paramMap()。

注3：各注解对值类型有约束（不匹配会抛 `IllegalStateException`），如下表：

| 注解 | 支持的值类型 |
| -------- | -------- |
| NotBlank / Pattern / Numeric / Date / Length / Email | String |
| NotEmpty | String 或 Collection |
| Size | Collection |
| NotZero / Max / Min / DecimalMax / DecimalMin / Range | 数字类型（int、long、double、Integer...） |
| AssertTrue / AssertFalse | boolean / Boolean |


### 1、三种校验机制

Solon 校验框架提供了三种层次的校验能力，理解它们有助于正确选择注解的加注位置：

| 机制 | 触发时机 | 实现方式 | 适用注解 |
| -------- | -------- | -------- | -------- |
| Context 校验（注入前） | 请求进入动作方法前，基于请求上下文（Header、Param、Cookie、Body、IP、Session 等） | `@Valid` 通过 `@Addition(ContextValidateHandler.class)` 挂载 Filter 实现 | 加在 **方法** 上的注解，如 @NoRepeatSubmit、@Whitelist、@Logined、@NotNull({"name","type"}) |
| 参数校验（注入后） | 参数注入完成后，动作方法执行前 | `@Valid` 通过 `BeanValidateInterceptor`（bean 拦截器）实现 | 加在 **参数** 上的注解，如 @NotNull String name |
| 实体校验（注入后） | 同上，随参数校验触发；也可手动调用 | `@Validated` 注解 + `BeanValidator` 实现 | 加在 **字段** 上的注解，如 User 实体里的 @Email |

> 组件类（非 web）场景下，Context 校验不适用，但参数校验与实体校验依然生效（经由 bean 拦截器）。


### 2、空值处理策略（重要约定）

大部分"格式类"校验注解（Date、Email、Pattern、Length、Numeric、Max、Min、DecimalMax、DecimalMin、Range、AssertTrue、AssertFalse）对 **空值（null 或 ""）一律放行**（视为通过），交由 @NotNull、@NotEmpty、@NotBlank 进一步控制"是否必填"。例如：

```java
//name 传 null 时 @Pattern 会放行，但 @NotBlank 会拦截
public void addUser(@NotBlank @Pattern("^http") String name){ ... }
```

即：**格式校验只管"格式"，是否必填由 @NotNull / @NotEmpty / @NotBlank 决定**。这与 JSR-380 的"空值跳过校验"约定一致。


### 3、分组校验

通过注解的 `groups()` 与 `@Validated(Xxx.class)` 配合实现"不同场景校验不同字段"：

```java
//标记分组：仅当使用 UpdateLabel 分组校验时才校验 id
public class User {
    @NotNull(groups = UpdateLabel.class)
    private Long id;

    @NotNull  //未声明 groups，任何分组下都校验
    private String nickname;
}

//新增场景：不校验 id
@Mapping("/user/add")
public void add(User user){ ... }  //此时需 @Validated User user 才触发实体校验

//更新场景：校验 id
@Mapping("/user/update")
public void update(@Validated(UpdateLabel.class) User user){ ... }
```

分组匹配规则（源码 `ValidatorManager.inGroup`）：

- 注解未声明 `groups`（默认空）→ 任何分组下都会执行校验；
- 注解声明了 `groups` → 仅当 `@Validated` 传入的分组与注解分组存在交集时才执行；
- `@Validated` 未传分组（默认空）→ 只校验"未声明 groups"的注解。

> 注：`@Validated(value)` 与 `@Validated(groups)` 是别名关系，两种写法等价。


### 4、关于 Context 的校验（即注入前校验）

加在控制器方法上的校验，为 Context 的较验（如 Header，Param，Cookie，Body，IP 等...）。可以做格式方面的校验（比如确保某参数是数字格式），还可以做限制性的校验（比如鉴权，比如白名单，比如流量限制等）。


```java
@Valid
@Controller
public class UserController {
    @NoRepeatSubmit  //重复提交验证（加上方法上的，为注入之前校验）
    @Whitelist     //白名单验证（加上方法上的，为注入之前校验）
    @NotNull({"name","type"}) //非Null验证（加上方法上的，为注入之前校验，可同时校验多个参数）
    @Mapping("/user/add")
    public void addUser(@Validated User user) //实体校验，需要加 @Validated
    { 
        //...
    }
}
```


### 5、开始定制使用

solon-validation 通过 ValidatorManager，提供了一组定制和扩展接口。当容器中存在以下接口的组件时，`ValidPlugin` 会通过 `getBeanAsync` **自动注册**（无需手动调用 setter）；也可以去掉 @Component 手动注册：

| 接口 | 自动注册的 setter | 作用 |
| -------- | -------- | -------- |
| NoRepeatSubmitChecker | ValidatorManager.setNoRepeatSubmitChecker | 重复提交检测 |
| LoginedChecker | ValidatorManager.setLoginedChecker | 登录状态检测 |
| WhitelistChecker | ValidatorManager.setWhitelistChecker | 白名单检测 |
| NotBlacklistChecker | ValidatorManager.setNotBlacklistChecker | 黑名单检测 |
| BeanValidator | ValidatorManager.setBeanValidator | 实体校验（可对接其它校验框架） |
| ValidatorFailureHandler | ValidatorManager.setFailureHandler | 校验失败处理 |


#### @NoRepeatSubmit 改为分布式锁验证

> 注意：v4.x 起，框架**不再内置** NoRepeatSubmit 的默认实现（旧的"本地延时锁"已移除）。未注册任何 `NoRepeatSubmitChecker` 时，使用 @NoRepeatSubmit 会抛出 `IllegalArgumentException("Missing NoRepeatSubmitChecker Setting")`，**必须自行实现**：

```java
@Component
public class NoRepeatSubmitCheckerNew implements NoRepeatSubmitChecker {
    @Override
    public boolean check(NoRepeatSubmit anno, Context ctx, String submitHash, int limitSeconds) {
        return LockUtils.tryLock(Solon.cfg().appName(), submitHash, limitSeconds);
    }
}

//或者去掉 @Component 手动注册到 ValidatorManager
//ValidatorManager.setNoRepeatSubmitChecker(new NoRepeatSubmitCheckerNew());
```

校验内容可通过注解控制（默认对 params 做 md5 摘要）：

```java
//对 params + body 做摘要，5 秒内不允许重复提交
@NoRepeatSubmit(value = {HttpPart.params, HttpPart.body}, seconds = 5)
@Mapping("/user/add")
public void addUser(){ ... }
```

或者 完全重写 NoRepeatSubmitValidator，并进行重新注册

#### @Whitelist 实现验证

框架层面没办法为 Whitelist 提供一个名单库，所以需要通过一个接口实现完成对接。**默认 checker 恒为 false（即默认全部拦截，返回 403）**，不实现该接口则白名单校验永远不通过。

```java
@Component
public class WhitelistCheckerNew implements WhitelistChecker {
    @Override
    public boolean check(Whitelist anno, Context ctx) {
        String ip = ctx.realIp();

        return CloudClient.list().inListOfServerIp(ip);
    }
}

//或者去掉 @Component 手动注册到 ValidatorManager
//ValidatorManager.setWhitelistChecker(new WhitelistCheckerNew());
```

或者 完全重写 WhitelistValidator，并进行重新注册

#### @NotBlacklist 实现验证

与 Whitelist 类似，默认 checker 恒为 false（即默认全部拦截，返回 403）。定制方式完全相同：

```java
@Component
public class NotBlacklistCheckerNew implements NotBlacklistChecker {
    @Override
    public boolean check(NotBlacklist anno, Context ctx) {
        String ip = ctx.realIp();

        return CloudClient.list().inListOfBlackIp(ip) == false;
    }
}
```

#### @Logined 定制登录校验

框架内置了默认实现 `LoginedCheckerImp`（基于 session 中 "user_id" 判断，数字须 > 0、字符串非空）。可整体替换：

```java
//默认 session 键名也可直接修改
//LoginedValidator.sessionUserKeyName = "login_user_id";

@Component
public class LoginedCheckerNew implements LoginedChecker {
    @Override
    public boolean check(Logined anno, Context ctx, String userKeyName) {
        //例如对接 solon-auth 或 JWT：从 header 取 token 校验
        String token = ctx.header("Authorization");
        return token != null && AuthUtil.verify(token);
    }
}
```

也可以在注解上指定 session 用户键名（仅默认实现下有效）：

```java
@Logined("admin_user_id") //使用 admin_user_id 键校验登录态
@Mapping("/admin")
public void admin(){ ... }
```

#### 替换 BeanValidator（对接其它校验框架）

`@Validated` 默认走 `BeanValidatorDefault`（即本框架的注解校验）。如需对接 hibernate-validator 等其它框架，实现 `BeanValidator` 接口注册即可：

```java
@Component
public class HibernateBeanValidator implements BeanValidator {
    @Override
    public Result validate(Object obj, Class<?>... groups) {
        //委托给 hibernate-validator 执行校验，返回 Result
        //...
    }
}
```


### 6、校验异常处理

校验失败默认由 `ValidatorFailureHandlerDefault` 抛出 `ValidatorException`（code 为校验失败码，如格式校验默认 400、白名单/黑名单为 403；message 为格式化后的提示消息，格式为 `@注解名 verification failed[: 描述]`）。可通过两种方式接管：

#### 通过过滤器（或，路由拦截器）捕捉异常

```java
//可以和其它异常处理合并一个过滤器
@Component
public class ValidatorFailureFilter implements Filter {
    @Override
    public void doFilter(Context ctx, FilterChain chain) throws Throwable {
        try {
            chain.doFilter(ctx);
        } catch (ValidatorException e) {
            //v1.10.4 后，添加 getCode() 接口；另有 getAnnotation() / getResult() / getMethod()
            if (e.getAnnotation() instanceof Logined) {
                ctx.status(401); //登录失败场景，可返回 401
            } else {
                ctx.render(Result.failure(e.getCode(), e.getMessage()));
            }
        }
    }
}
```

`ValidatorException` 主要属性：

| 属性/方法 | 说明 |
| -------- | -------- |
| getCode() | 校验失败状态码（格式校验默认 400；Whitelist/NotBlacklist 为 403） |
| getMessage() | 已格式化的提示消息 |
| getAnnotation() | 触发失败的校验注解 |
| getResult() | 校验结果（含 description 描述） |
| getMethod() | 触发失败的动作方法（参数/实体校验时携带） |

#### 定制 ValidatorFailureHandler 接口的组件，构建提示信息（可选，一般默认的就够了）

```java
//通过定义 ValidatorFailureHandler 实现类的组件，实现自动注册。
@Component
public class ValidatorFailureHandlerImpl implements ValidatorFailureHandler {
    @Override
    public boolean onFailure(Context ctx, Annotation anno, Result rst, String message) throws Throwable {
        //可以对 message 作国际化转换（校验注解可以配置消息的 code，此处统一转换）
        //注意：返回值 true 表示"停止后续校验器"；false 表示继续
        if (Utils.isEmpty(message)) {
            if (Utils.isEmpty(rst.getDescription())) {
                message = new StringBuilder(100)
                        .append("@")
                        .append(anno.annotationType().getSimpleName())
                        .append(" verification failed")
                        .toString();
            } else {
                message = new StringBuilder(100)
                        .append("@")
                        .append(anno.annotationType().getSimpleName())
                        .append(" verification failed: ")
                        .append(rst.getDescription())
                        .toString();
            }
        }
        //这里也可以直接做输出，不过用异常更好
        throw new ValidatorException(rst.getCode(), message, anno, rst);
    }
}

//也可以手动配置（找个地方写一下）
//ValidatorManager.setFailureHandler((ctx, ano, rst, message) -> {
//    //..
//});
```

#### validateAll=true 时的定制处理

开启 `validateAll` 后，失败处理路径与默认模式不同，定制时有两个关键点：

**坑点 1：`ValidatorFailureHandler` 的触发点与调用次数**

- `validateAll=true` 时，**参数校验**的聚合出口（`validateOfInvocation`）会调用一次 `failureDo()`（传入聚合结果与首个失败项注解），因此自定义 `ValidatorFailureHandler`（含 i18n 实现）在参数校验下**依然生效**，只是调用次数从"每个失败项一次"变为"聚合一次"；
- **实体校验**（`ValidUtils.validateEntity` 手动触发）不走 `failureDo()`，直接抛 `ValidatorException`，定制入口应捕捉该异常处理。

**坑点 2：消费 `List<BeanValidateInfo>` 时优先用字段明细**

`validateAll=true` 时 `Result.data` 为 `List<BeanValidateInfo>`，异常 `getMessage()` 是聚合消息（可读，但字段级结构化信息在列表里）。**推荐从 `e.getResult().getData()` 取列表做结构化响应**，`getMessage()` 可作兜底展示。

**推荐做法：用过滤器/路由拦截器统一接管 `ValidatorException`**

```java
@Component
public class ValidatorFailureFilter implements Filter {
    @Override
    public void doFilter(Context ctx, FilterChain chain) throws Throwable {
        try {
            chain.doFilter(ctx);
        } catch (ValidatorException e) {
            Object data = (e.getResult() == null ? null : e.getResult().getData());

            if (data instanceof List) { //validateAll=true：收集到的全部失败项
                List<BeanValidateInfo> infos = (List<BeanValidateInfo>) data;
                List<Map<String, String>> details = infos.stream().map(info -> {
                    Map<String, String> m = new HashMap<>();
                    m.put("field", info.name);
                    m.put("message", info.message);
                    return m;
                }).collect(Collectors.toList());
                ctx.render(Result.failure(e.getCode(), e.getMessage(), details));
            } else {
                //快速失败模式，或 Context 校验（@Logined/@Whitelist/@NoRepeatSubmit 等）：
                //validateAll 模式下这类注解仍走 failureHandler，data 不是 List，按单条处理
                if (e.getAnnotation() instanceof Logined) {
                    ctx.status(401); //登录失败场景，可返回 401
                } else {
                    ctx.render(Result.failure(e.getCode(), e.getMessage()));
                }
            }
        }
    }
}
```

> 说明：`validateAll=true` 时，`@Logined`/`@Whitelist`/`@NoRepeatSubmit` 等 Context 校验注解**依然走 `failureHandler`**，其抛出的异常 `getResult().getData()` 不是 `List<BeanValidateInfo>`，需按单条分支处理（即上面的 else 分支）。

**请求级动态切换（推荐）**

框架提供 **ThreadLocal 请求级覆盖**（不影响全局与其他线程），适合"部分接口收集全部失败、其余快速失败"的细粒度策略：

```java
//按路径临时开启（示例：仅 /batch 接口收集全部失败）
public void doFilter(Context ctx, FilterChain chain) throws Throwable {
    boolean batch = ctx.path().startsWith("/batch");
    if (batch) {
        ValidatorManager.validateAll(true);
    }
    try {
        chain.doFilter(ctx);
    } finally {
        ValidatorManager.clearValidateAll(); //务必在 finally 中清理，防止 ThreadLocal 泄漏
    }
}
```

> 说明：`validateAll(boolean)` / `clearValidateAll()` 仅作用于**当前线程**，与全局静态字段 `VALIDATE_ALL` 互不影响（请求级优先）。若仍需修改全局行为，直接写 `ValidatorManager.VALIDATE_ALL` 即可，但注意全局修改对并发请求是立即可见的。

#### 添加 @Date 的校验器实现类

实现 `Validator<T>` 接口，共五个方法：`message()`、`groups()`、`isSupportValueType()`、`validateOfValue()`、`validateOfContext()`。其中 **`isSupportValueType()` 用于声明该校验器支持的值类型**（不匹配会抛 IllegalStateException），建议实现：

```java
public class DateValidator implements Validator<Date> {
    public static final DateValidator instance = new DateValidator();

    @Override
    public String message(Date anno) {
        return anno.message();
    }

    @Override
    public Class<?>[] groups(Date anno) {
        return anno.groups();
    }

    @Override
    public boolean isSupportValueType(Class<?> type) {
        return String.class.isAssignableFrom(type);
    }

    /**
     * 校验实体的字段（注解在参数或字段上有效，即注入后的校验）
     * */
    @Override
    public Result validateOfValue(Date anno, Object val0, StringBuilder tmp) {
        if (val0 != null && val0 instanceof String == false) {
            return Result.failure();
        }

        String val = (String) val0;

        if (verify(anno, val) == false) {
            return Result.failure();
        } else {
            return Result.succeed();
        }
    }

    /**
     * 校验上下文的参数（注解在方法上有效，即注入前的校验）
     * */
    @Override
    public Result validateOfContext(Context ctx, Date anno, String name, StringBuilder tmp) {
        String val = ctx.param(name);

        if (verify(anno, val) == false) {
            return Result.failure(name);
        } else {
            return Result.succeed();
        }
    }

    private boolean verify(Date anno, String val) {
        //如果为空，算通过（交由 @NotNull 或 @NotEmpty 或 @NotBlank 进一步控制）
        if (Utils.isEmpty(val)) {
            return true;
        }

        try {
            if (Utils.isEmpty(anno.value())) {
                DateTimeFormatter.ISO_LOCAL_DATE_TIME.parse(val);
            } else {
                DateTimeFormatter.ofPattern(anno.value()).parse(val);
            }

            return true;
        } catch (Exception ex) {
            return false;
        }
    }
}
```

补充说明（源码细节）：

- 实体校验会同时校验 **字段上的注解** 与 **public 无参方法（如 getter/isXxx）上的注解**，例如 `@AssertTrue public boolean isValid()`；
- `@Validated` 加在 List/Map 类型字段上时，会逐个校验集合里的实体（嵌套校验）；
- `validateAll=true` 时，实体校验会收集所有失败项（`Result.data` 为 `List<BeanValidateInfo>`，每个失败项含 `name`（字段名/参数名）、`anno`、`message`、独立 `code`）；在参数校验路径下（如 `@Validated User user` 参数），这些失败项会与参数注解的失败项**合并到同一个列表**，最终统一以"；"拼接成消息抛出（消息按 `name: message` 格式、未配置 message 自动兜底，异常 `getAnnotation()`/`getCode()` 均以**首个失败项**为准，详见上文『validateAll』相关小节）；
- 校验参数时若注解与参数类型不匹配（如 @Size 加在 String 上），会抛 `IllegalStateException`。
